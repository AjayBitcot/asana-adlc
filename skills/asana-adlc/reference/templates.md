# Templates

Fill every `<…>` from engine output (`adlc status --task <gid> --json`). Plain, short sentences.
The engine redacts and appends the dedupe marker to Asana comments; still never paste secrets,
`.env` values, or raw environment dumps.

## Stage updates to the user

```
<Stage name> — <done | needs your decision | blocked>
Found: <1–3 lines>
Did: <what changed, verified by …>
Failed / not run: <item — reason | none>
Next: <next action>  (needs approval: <yes — what | no>)
```

## Confirmation prompt

```
Next: <action>
Affects: <branch/remote/Asana task/files/services>
Expected: <outcome>
Not affected: <user's checkout, other branches, …>
Proceed?
```

## Asana comments (`adlc asana comment --key <key> --file <txt>`)

| Key | Text |
|---|---|
| `claimed` | 🤖 ADLC: picked up for development. Next: analysing the codebase and preparing a plan for approval. |
| `analysis` | 🤖 ADLC: plan ready — `<2–3 line summary>`. Files: `<n>` changed, `<n>` new. Data changes: `<none / summary>`. Criteria mapped: `<n>/<n>`. |
| `implementation` | 🤖 ADLC: implementation and tests complete. Checks: `<name ✅ / ❌ pre-existing / ⏭ not run (reason)>`, … |
| `validation-failed` | 🤖 ADLC: validation failing — `<check>`: `<≤10 relevant lines>`. Not pushed. Next: `<plan>`. |
| `blocked-<stage>` | 🤖 ADLC: blocked at `<stage>`. Reason: `<one line>`. Needed: `<questions / action>`. |
| `pr-created` | 🤖 ADLC: Pull Request opened`<, as draft because …>`: `<url>`. Ready for code review — not approved or merged. |

`sync` writes its own short comments (`approved-<n>`, `changes-requested-<n>`, `merged-<n>`, `pr-closed-<n>`).

## PR body

```markdown
## Summary
<what changed and why, 2–5 sentences>

**Asana task:** [<task name>](<task url>) (`ASANA-<gid>`)

## Implementation approach
<key decisions; how it follows the project's existing architecture; deviations and why>

## Acceptance criteria
| Criterion | Implementation | Test |
|---|---|---|
| <criterion> | <file / symbol> | <test name> |

## Validation
| Check | Command | Baseline | Result |
|---|---|---|---|
| <name> | `<command>` | <baseline> | <final (classification)> |

Not run: <check — exact reason | None>

## Data / schema changes
<changes and how they roll back | None>

## Risks and follow-ups
<regression risks reviewed, known limitations, follow-up work | None>

---
Generated by the asana-adlc workflow (run `<run_id>`). Ready for review — not approved, merged, or deployed.
```

## Execution report

```
ASANA ADLC — <full run | Soft Run> report
Task        <gid> · <name>  <url>
Run         <run_id>   status <status>   stage <n> (<name>)
Stack       <stacks / frameworks>
Branch      <branch> from <base_ref> @ <base sha>
Changed     <n files: list>
Checks      <name>: baseline <…> → final <…> [<classification>]
Validation  <state>
Push        <pushed @ sha | not pushed: reason>
PR          <url (ready|draft) | not created: reason>
Asana       <operation: result>, …
Cleanup     removed <n> · kept <list + reason> · needs approval <list + reason> · failed <list>
Evidence    <run_dir>/evidence/, <run_dir>/logs/
Follow-ups  <items | none>
```

### Soft Run report

Same as above, with `Push`/`PR`/`Asana` replaced by `Remote writes: none` (or each separately
approved override), and `Branch` showing the temporary `adlc-soft/…` branch and whether it was
removed.
